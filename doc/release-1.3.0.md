# Cloud Mail v1.3.0

## 界面与交互

- 验证码中心使用居中的本地单环刷新 SVG，统一线宽与留白；刷新按钮采用中性描边，与等待按钮对齐。仅真实列表请求期间旋转并禁用重复点击，失败后可重试；支持键盘焦点和减少动态效果，不改变验证码隐藏规则与轮询逻辑。

- 对象存储的访问域名改为独立展示区：标签与编辑按钮在上，完整域名在下。增加明确间距、中性背景和本地图标；长域名自动换行，未配置时显示对应语言提示。
- 清理旧域名网格与按钮外边距规则，避免与新版系统设置按钮样式互相覆盖。保留 S3 配置和存储类型的原有操作。
- 域名帮助支持鼠标和键盘焦点；触屏保留较大的点击目标，支持浅色、深色和四种界面语言。
- 域名编辑支持 Enter 保存，阻止浏览器原生表单跳转；重复提交仍由保存锁拦截。重新打开时读取最新值，粘贴时去除首尾空格，保留清空域名的能力。

## 回归修复与版本

- 系统设置的其余表单也阻止原生提交跳转，不改变它们的保存、删除和确认操作。
- 修正两组 Turnstile 选项和全站邮件状态选项的重复 key，保持原有数值和查询参数不变。
- 前后端 package.json 统一为 1.3.0；系统设置直接读取前端包版本，避免展示版本与发布版本分叉。
- 更新提示按稳定版本的主、次、修订号比较；旧版、相同版本、无效标签和预发布标签不再误报为新稳定版。
- 新增域名交互、版本比较、所有 Vue 模板静态重复 key 的回归测试。

## 验证与边界

执行 `node scripts/verify.mjs` 验证发布配置、后端测试、前端测试及正式前端构建。另使用 Chromium 内存页面挂载实际编译的系统设置页面，检查不同宽度、主题、语言、长域名、触屏目标、键盘操作及保存成功/失败/重试。

浏览器检查使用合成状态和 API 替身，不执行生产登录、配置修改或真实邮件投递。不新增依赖，不改变锁文件、后端业务逻辑、数据库、生产密钥、资源绑定、权限边界、验证码规则或发送语义。

## 发布

main 的完整 CI 通过后，独立的发布任务创建 `v1.3.0` 标签和正式 GitHub Release，并设为 Latest。发布目标固定为通过验证的提交；已有正式 Release 不被覆盖，已有不同指向的标签不会被强行移动。前后端版本不一致、无效事件或冲突会阻止发布，后续版本不会被这个 v1.3.0 专用任务自动发布。

本次源码发布包含此前已合并的邮件阅读隔离、私密附件访问、验证码中心、草稿交互和选择器优化。对象存储独立公开域名、旧公共缓存和 Telegram 外部预览仍需按既有部署说明管理；本次不更改生产存储权限，也不将 CI 通过等同于生产收发信验收。
